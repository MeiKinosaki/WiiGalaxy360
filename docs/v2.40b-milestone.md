# WiiGalaxy360 — marco v2.40b

## O que foi concluído neste marco

- O workflow **Host tests** do commit `05200faceb6991b9fe8addc9162cda85e3589acb` terminou com **success**: https://github.com/MeiKinosaki/WiiGalaxy360/actions/runs/43647958974.
- Corrigidas as expectativas antigas dos testes de regressão para refletir que falhas de acesso agora redirecionam o PC para os vetores de exceção.
- A CPU C registra exceções iniciais de reset, machine check, data storage, instruction storage, external, alignment, program e system call.
- Acessos desalinhados de meia-palavra/palavra disparam o vetor de alinhamento; falhas de acesso a dados disparam data-storage; falha na busca de instrução dispara instruction-storage.
- O estado serializado inclui os campos iniciais de exceção e mantém o formato interno versionado documentado no código.
- O controlador genérico de interrupções possui testes de pendência, máscara/enable, limpeza e prioridade; a entrega de interrupção externa ao CPU tem uma interface inicial e testes.

## O que ainda não está concluído

- O mecanismo de exceção é apenas inicial: MSR, SRR1 fiel, estados privilegiados, retorno de exceção e semântica completa Broadway ainda faltam.
- O controlador de interrupções é genérico e ainda não modela fielmente o hardware Wii nem integra todas as fontes reais.
- Não há mapa Wii completo, MMU/TLB, FPU Gekko, GX/Flipper funcional, DSP/IOS ou execução de jogos demonstrada.
- O workflow validado é **Host tests**. Este marco não comprova compilação Xenon, geração de um novo `default.xex`, inicialização em Xbox 360 RGH ou boot de jogos Wii.
- Save states e frontend continuam parciais; configurações e protótipos não equivalem a integração nativa.

## Próximo marco técnico

Integrar a política de interrupções ao estado arquitetural da CPU (MSR/EE), implementar retorno de exceção com instrução apropriada e adicionar testes de prioridade/mascaramento. Depois avançar para mapa real MEM1/MEM2 e tradução de endereços, sem marcar MMU concluída antes dos testes.
